LeetCode Hot 100 Day 01 — 哈希表

哈希表的本质：用空间换时间，把 O(n) 的查找降到 O(1)。今天 3 道题，三种典型用法：查找配对、分组归类、去重计数。

题 1：两数之和（#1 Easy）

题目速览

给整数数组 nums 和目标值 target，返回数组中和为 target 的两个元素的下标。保证恰好有一个解，同一元素不能重复用。

思路推演

第一反应（暴力）：两层循环，枚举所有 (i, j) 对，判断 nums[i] + nums[j] == target。

n 大了就慢。能不能只遍历一次？

关键观察：对于当前元素 nums[i]，我要找的是 target - nums[i] 这个数在不在前面出现过。「前面出现过哪些数」 → 这正是哈希表擅长的 O(1) 查找。

最优解：边遍历边把数存进 HashMap。对每个 nums[i]，先查 target - nums[i] 在不在 map 里：

  • 在 → 找到了，返回两个下标
  • 不在 → 把 nums[i] 存进 map，继续

为什么是「边查边存」而不是「先全存再查」？ 先全存的话，查到 target - nums[i] 时可能查到自己（同一个元素用了两次），还得额外判断下标是否相等。边查边存天然保证查的是「之前」的元素，绝不会用到自己。

复杂度

  • 时间：O(n)，一次遍历
  • 空间：O(n)，最坏存 n-1 个元素

面试要点

  • map 存什么：value → index（因为要返回下标，不是值）
  • 边查边存：避免用到自己，省去下标判等
  • 变种：如果数组有序 → 双指针 O(n) 也能做（两数之和 II）；如果要求所有解或三个数 → 见 #15 三数之和

🔑 一句话模板：for each num: if (target - num) in map: return; else map[num] = index

题 2：字母异位词分组（#49 Medium）

题目速览

给字符串数组 strs，把字母异位词（字母组成相同、排列不同，如 "eat" 和 "tea"）分到同一组，返回分组列表。

思路推演

异位词的本质：字母组成相同。怎么判断两个字符串字母组成相同？只要能找到一个「相同就归一类」的 key，就能用 HashMap 分组。

方案 A：排序做 key。"eat" / "tea" / "ate" 排序后都是 "aet"。排序后的字符串作为 key，原字符串塞进对应桶。

方案 B：计数做 key。统计 26 个字母的出现次数，计数序列作为 key（如 "aab" → (2,1,0,0,...)）。

两种都行。面试时先讲排序版（直观），再优化到计数版（展示对复杂度的敏感）。

复杂度

方案 时间 空间
排序 key O(n·k·log k) O(n·k)
计数 key O(n·k) O(n·k)

Java（计数版，展示 O(n·k) 优化；computeIfAbsent 一行建桶）：

面试要点

  • key 的选择：排序（直观）vs 计数（快），能说出 trade-off 是加分项
  • Java 计数转 key 的坑：必须加分隔符（#），否则 "1" + "11" 和 "11" + "1" 会生成相同 key
  • computeIfAbsent：Java 建桶的惯用写法，比 containsKey + put 简洁
  • Python defaultdict(list)：自动给不存在的 key 建空 list，省去判空

🔑 一句话模板：找「同类」→ 提取一个稳定 key → HashMap<key, List> 分桶

题 3：最长连续序列（#128 Medium）

题目速览

给未排序整数数组 nums，找最长连续整数序列的长度。要求 O(n) 时间。

例：[100,4,200,1,3,2] → 最长连续序列是 [1,2,3,4]，长度 4。

思路推演

第一反应（排序）：排序后扫一遍找最长连续段。

关键观察：题目要求 O(n)，排序这条路堵死。但我们只需要判断「某个数在不在数组里」→ HashSet O(1) 查找。

核心技巧：只从「序列起点」开始数。什么是起点？num - 1 不在集合里的那个数。比如 1 是起点（0 不在），2 不是起点（1 在）。只从起点往后数 num+1, num+2, ...，就不会重复计数。

为什么是 O(n)：虽然看起来有嵌套 while，但每个数最多被访问两次（一次在外层 for 判断是不是起点，一次在内层被某个起点数到）。总访问 O(n)。

复杂度

  • 时间：O(n)（每个元素最多访问 2 次）
  • 空间：O(n)（HashSet）

Java（HashSet）：

面试要点

  • num - 1 not in set 是灵魂：没有这个判断，每个数都会触发 while，退化成 O(n²)
  • 遍历 set 而非原数组：天然去重，避免重复元素浪费时间
  • 复杂度怎么证的：每个元素在内层 while 里最多被「数」一次 → 总 O(n)。面试常问，要答得出。
  • 变种：返回序列本身（而非长度）→ 起点开始数时记录；带重复元素 → set 自动去重不影响

🔑 一句话模板：要 O(n) 处理连续区间 → HashSet + 只从起点（前驱不存在）开始延展

面试高频追问

Q：HashMap 和 HashSet 的区别？什么时候用哪个？

HashSet 本质是「只存 key、value 为固定占位」的 HashMap。需要存「值→额外信息（下标、计数、列表）」用 Map；只需要判断「在不在」用 Set。#1 要存下标用 Map，#128 只判断存在用 Set。

Q：Java 的 HashMap 时间复杂度真是 O(1) 吗？

平均 O(1)，最坏（哈希冲突严重，退化成链表）是 O(n)。Java 8 后冲突链表超过 8 会转红黑树，最坏降到 O(log n)。面试答「平均 O(1)，理论最坏 O(log n)（链表转树后）」更严谨。

Q：Python 的 dict 为什么查找是 O(1)？

底层是哈希表。但要注意：Python 的 dict 从 3.7 起保证插入顺序，且内存比想象中优化得好（紧凑存储）。in 操作平均 O(1)。

延伸：从两数之和到三数之和、k 数之和（双指针与降维）

两数之和的「变种」里提到：数组有序 → 双指针；三个数 → 三数之和。这一节把这条线彻底走通：有序两数之和（双指针）→ 三数之和（降维）→ k 数之和（递归通解）。这是双指针最经典的一根主线，也是日后 Day 02 双指针应用的地基。

如果数组有序，连哈希表都不用。left 指向最小、right 指向最大，只有两种动法：left++（和变大）、right--（和变小）。

4. 递归到底在做什么（+ 回溯 cur 栈）

递归 = 把多层嵌套循环折叠成一个函数。4-sum 最笨是 4 层 for 循环，每层起点后挪一位（保证不重复挑）；递归每调一次 = 进入下一层循环。最里面 2 层用双指针一次搞定，所以到 k==2 就停。

回溯三件套（Java 共用一个 cur，必须选择/撤销配对）：

cur 本质是个栈（后进先出）：走到哪记到哪，退回也跟着退，任何时候 cur 都等于”从递归树根到当前节点”这条路。

  • remove(size-1)：删最后一个元素 = 弹出最后压入的，永远精确撤掉当前层刚加的（不能用 remove(nums[i]) 按值删，有重复值会删错）。
  • 不撤会怎样：cur 残留垃圾，越积越满，后面结果全错。

🔑 一句话串起整条线：哈希 2-sum（无序）→ 双指针 2-sum（有序）→ 固定一个降维成 3-sum → 再固定一个成 4-sum → 通用 k-sum。排序是地基，去重是难点，递归是写法，回溯是状态管理。

5. DP 的本质：回溯 → 记忆化 → DP

DP 不是凭空发明的——它是从回溯优化来的。两者的血缘关系：DP = 回溯 + 缓存。

记忆化递归和回溯的区别，只有两行：

跟回溯比只是加了缓存，却把 O(2ⁿ) 降到了 O(n²)——用数组空间换掉了回溯树的整棵子树。

什么时候用回溯，什么时候用 DP？

是否存在 DP

🔑 只问值用 DP，问全部解用回溯。DP 就是给回溯加了个备忘录。

6. 最长递增子序列 #300 — 状态转移公式推导

状态定义：dp[i] = 以 nums[i] 结尾的最长递增子序列长度。

公式怎么来的：在纸上手动求一遍——走到 nums[i]，往左看所有比它小的数，挑一个”最长的”接上去。

代码 对应手动操作
j < i 只往左看（子序列保序）
nums[j] < nums[i] 比我小的才能接（递增）
dp[j] + 1 接在它后面，长度 +1
Math.max 能接的人里选最长的

Java（基础 DP，O(n²)）：

走例 [10,9,2,5,3,7,101,18]：

i nums[i] 往左找比我小的 dp[i] 推导 dp[i]
3 5 j=2(2): dp[2]+1 1+1=2 2
4 3 j=2(2): dp[2]+1 1+1=2 2
5 7 j=3(5)→3, j=4(3)→3 max=3 3
6 101 j=5(7)→3+1 4 4

maxLen = 4（[2,3,7,101]）。

🔑 DP 公式不是背的——先手动求，发现「每走一步往左看、找比我小的、挑最长的接上去」，再翻译成 dp[j] + 1 / Math.max。
