Q1：LoRA 的原理？为什么有效？rank 怎么选？

展开答案

核心原理

LoRA 在冻结的原权重 W 旁注入低秩矩阵 A 和 B——用 A×B 近似全量微调的 ΔW。A 降维（d_in → r），B 升维（r → d_out），秩 r 控制参数量。原本 16M 参数的矩阵只需训 ~13 万参数，少了 100 多倍。A 随机小值初始化打破对称，B 零初始化保证训练从零起步。推理时 A×B 可直接合并进 W，零额外延迟。rank 选 r=8 经典默认，不够试 r=16；太小表达不足，太大收益递减且可能过拟合。

面试话术

“冻 W + 旁路 A×B，只训两个小矩阵。d² 参数降到 2dr，省 100+ 倍。A 随机、B 零初始化，推理 merge 零延迟。r=8 默认，不够调 16。为什么有效？ΔW 低秩假设——适配只需要改几个方向。”

易混淆点

  • ❌ “LoRA 不改 W 所以推理时多了一次矩阵乘法” → ✅ 推理前 A×B 直接加进 W，形状一致，零额外延迟
  • ❌ “r 越大越好” → ✅ r>64 收益递减且可能过拟合

Q2：全量微调 70B 要多少显存？LoRA 省多少？

展开答案

核心原理

全量微调 70B：FP16 权重 140GB + Adam 优化器状态 420GB + 梯度 140GB + 激活值 ~100GB，总计 ~660GB，至少 8×A100。LoRA r=16：基座权重仍占 140GB，但优化器只需 ~240MB，总计 ~140GB，2×A100 够用。显存省了 ~4.7×。

面试话术

“全量 70B→660GB →8×A100。LoRA→W 占 140GB 但优化器从 420GB→240MB →2×A100。省在优化器——冻 W 不用存 Adam。”

易混淆点

  • ❌ “LoRA 省了 W 的显存” → ✅ W 还是 FP16 全精度，省的是优化器状态和梯度

Q3：QLoRA 是什么？和 LoRA 的区别？

展开答案

核心原理

QLoRA 在 LoRA 的基础上把基座 W 量化到 4-bit NF4 格式——反正 W 冻住不训练，没必要 16-bit。65B 模型从 130GB 压到 32GB，单张 A100 就能微调。关键技术：NF4 量化格式（专门为神经网络权重设计）+ 双重量化 + 分页优化器。精度损失 <2%，显存省 4×。

面试话术

“LoRA 冻 W 但还要 FP16 加载。QLoRA 把 W 压到 4-bit NF4——130GB→32GB →单卡 A100 微调 65B。精度掉不到 2%。反正 W 不训，高精度浪费。”

易混淆点

  • ❌ “QLoRA 和 LoRA 一样快” → ✅ 推理时需反量化，比正常 LoRA 慢一些，但显存省得多

Q4：RLHF 三阶段流程？四个模型各干什么？

展开答案

核心原理

三个阶段——SFT（人类写回答 → 监督微调，教会”好回答”长什么样）、RM（偏好数据训练奖励模型，学会给回答打分）、PPO（四个模型同时跑：Policy 生成回答 → RM 打分 → Reference 做 KL 约束防跑偏 → Value 提供基线算 Advantage → PPO 用 Advantage 更新 Policy）。

四个模型各司其职：Policy 被训的 LLM、RM 提供奖励信号、Reference 提供约束锚点（防作弊）、Value 提供对比基线（判断”这分数算高还是低”）。

面试话术

“SFT 教说话 → RM 教打分 → PPO 用打分和 KL 约束练。PPO 时四模型同跑——Policy 训练、RM 打分、Ref 防跑偏、Value 算基线。Reference 是 SFT 副本冻住，KL 散度限制 Policy 不能变太远。”

易混淆点

  • ❌ “RM 打分是最终结果” → ✅ RM 只是给中间分数，PPO 用这个分数 + KL 约束来更新 Policy

Q5：DPO 和 PPO 的区别？为什么 DPO 更流行？

展开答案

核心原理

PPO 需要 4 个模型同时跑——Policy、Reference、RM、Value——RM 需单独训练，Value 需单独训练，PPO 循环不稳定、容易 Reward Hacking。DPO 只需要 2 个模型——Policy + Reference。核心创新：用 Policy 输出概率和 Reference 输出概率的比值，替代 RM 的打分功能（数学上等价）。干掉了 RM 和 Value，不是 RL 所以不需要 Advantage。训练更稳定、计算开销更低、效果相当。

面试话术

“PPO 四模型、训 RM 贵且不稳。DPO 两模型——Policy/Ref 概率比替代 RM 打分，数学等价。干掉 RM+Value，稳定，省算力。2025 主流。”

易混淆点

  • ❌ “DPO 不需要 Reference” → ✅ DPO 也要 Reference 做 KL 约束，只是不需要 RM 和 Value
