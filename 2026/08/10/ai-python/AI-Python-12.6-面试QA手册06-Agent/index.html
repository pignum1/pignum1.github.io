Q1：Agent 核心四要素？

展开答案

核心原理

规划——把大任务分解成子任务，决定先做什么后做什么。记忆——短期记忆存对话上下文，长期记忆存用户偏好和历史，情节记忆存完整任务执行轨迹。工具——Function Calling 或 MCP 调外部 API。执行——实际调用工具、获取结果、写入记忆、生成回复。

面试话术

“四要素——规划（拆任务排优先级）、记忆（短/长/情节三层）、工具（FC+MCP 调外部）、执行（调工具→拿结果→写记忆→出回复）。ReAct 把规划和执行串一起。”

Q2：ReAct 框架的执行流程？

展开答案

核心原理

ReAct = Reasoning + Acting 交替循环。Thought（分析当前状态，判断需要什么信息）→ Action（调用对应工具）→ Observation（拿到返回结果）→ 基于结果重新 Thought → 信息够了输出 Final Answer。是 CoT 的扩展——纯推理变成了”推理→行动→观察→再推理”。

面试话术

“Thought→Action→Observation 循环。每次思考决定下一步——需调工具→调，信息够了→输出答案。CoT 只推理不行动，ReAct 加行动加观察。所有 Agent 的标准模式。”

Q3：Function Calling 流程？和 ReAct 的关系？

展开答案

核心原理

FC 不是模型直接调工具。四步——注册工具给 LLM → LLM 返回要调哪个函数和参数 → 你的代码执行工具 → 结果发回 LLM。LLM 只负责”决定调什么”，不负责”执行”。ReAct 是概念框架（为什么这样做），FC 是技术实现（怎么做）。不支持 FC 的模型可以用 Prompt 描述工具 + MCP 调工具。

面试话术

“FC 四步——注册工具→LLM 返回 tool_call→代码执行→结果送回 LLM。LLM 只决策不执行。ReAct 是框架，FC 是 ReAct 中 Action 的技术实现。MCP 管工具连接，FC 管决策格式。”

易混淆点

  • ❌ “FC 就是 MCP，MCP 就是 FC” → ✅ FC=LLM 输出格式，MCP=工具连接协议，上下层配合，不互斥

Q4：Tool 封装（三种方式）/ 路由 / 权限？

展开答案

核心原理

封装三种——@tool 装饰器最快（2 行），StructuredTool 支持自定义 name 和默认值，BaseTool 子类化支持内部状态和异步。路由——LLM 根据工具描述自动选择，API 请求带上所有工具的 name+description+Schema。权限三层——工具层鉴权（API Key+只读账号）、Agent 可见性（不可见工具 LLM 不知道存在）、业务前置校验（关键操作需 HITL）。

面试话术

“@tool 最快，StructuredTool 更灵活，BaseTool 支持内部状态。路由靠 LLM 读描述自选。权限三层——工具鉴权、Agent 可见性、业务前置+ HITL。”

Q5：记忆系统——短期/长期/情节记忆？

展开答案

核心原理

短期记忆——当前会话 K 轮对话窗口，超出触发压缩/裁剪，保留关键信息不超 Token 限制。长期记忆——跨 Session 持久化到 DB，包括用户偏好、历史关键对话。当前短期记忆不够覆盖时从 DB 语义检索加载。情节记忆——记录完整任务执行轨迹，下次类似问题通过语义搜索复用排查路径。LangGraph Checkpointer 在每个节点执行后自动保存 State 快照。

面试话术

“短：K 轮窗口，超了压缩裁剪。长：DB 持久化，不够查历史。情：存任务轨迹，复用排查路径。Checkpointer 自动存 State，同一 thread_id 自动恢复。”

Q6：LangGraph vs LangChain Agent？

展开答案

核心原理

LangChain Agent 是 ReAct 循环的黑盒封装——流程固定、不可干预，适合简单问答。LangGraph 把 Agent 拆成节点和边组成的有向图——每个节点独立执行、边定义条件分支、支持并行和条件路由、支持状态持久化和中断恢复。简单用 LangChain，复杂用 LangGraph。

面试话术

“LangChain=ReAct 黑盒，固定流程。LangGraph=节点+边有向图，支持并行/条件/持久化。简单够用不升级，复杂多步上 LangGraph。”

Q7：多 Agent 协作——Supervisor vs Pipeline？

展开答案

核心原理

Supervisor——一个 Leader Agent 负责任务拆分、分配、状态追踪。子 Agent 各司其职，执行完汇报，Leader 决定下一步。适合任务不确定、需动态决策。Pipeline——业务流程固化为流水线，每节点一个 Agent，数据按固定顺序流转。Supervisor 灵活但慢（多轮调度开销），Pipeline 快但不灵活。

面试话术

“Supervisor=Leader 动态分任务，子 Agent 汇报再决策，灵活但慢。Pipeline=固化流程，固定顺序走，快但不灵活。不确定用 Supervisor，稳定流程用 Pipeline。”

Q8：MCP 协议原理？和 Function Calling 区别？

展开答案

核心原理

MCP 是 Anthropic 发布的开放协议，基于 JSON-RPC。四层架构——Host 管应用和权限、Client 管连接和消息路由、Transport 管传输（stdio/HTTP+SSE）、Server 暴露三大原语（Resources 只读、Tools 可执行、Prompts 可复用）。和 FC 区别——FC 是部分模型的输出格式（决定调哪个工具），MCP 是通用通信协议（工具连到哪）。FC 依赖模型能力，MCP 模型无关。FC 管决策，MCP 管连接。

面试话术

“MCP=四层 JSON-RPC 协议，模型无关。FC=模型输出格式，挑模型。MCP 连接、FC 决策，上下配合不互斥。FC 不支持时 Prompt 描述+MCP 调工具。”

Q9：Human-in-the-Loop 怎么实现？

展开答案

核心原理

四种自主程度——Human-in-command、Human-as-filter、Human-on-the-loop、Human-as-backup。三种实现——Conditional Edge（条件路由到人工）、Interrupt（interrupt_before 暂停等确认）、State Checkpoint（状态序列化恢复）。操作分级：P0 必须审批（删数据/发邮件）、P1 审核日志、P2 全自动（搜索）。The Boy 目前不需要 HITL——工具层只有只读权限。

面试话术

“HITL=关键操作暂停等人确认。四种自主度+三种实现（条件边/中断/检查点）。操作分 P0/P1/P2 依风险定。The Boy 无危险操作所以不需要。LangGraph interrupt_before+Checkpointer 实现。”
