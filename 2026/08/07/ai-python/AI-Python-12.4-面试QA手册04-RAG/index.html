Q1：RAG 完整流程？和微调的区别？

展开答案

核心原理

RAG 四个阶段——清洗（文档解析、去噪、多模态提取）、分块（按策略切分+向量化）、检索（混合检索+RRF+Reranker）、生成（Top-K 注入 Prompt → LLM 生成带引用回答）。和微调区别：对象不同——RAG 管外部知识库，微调管模型参数；时机不同——RAG 推理时检索增补，微调训练时固化知识；适用不同——RAG 适合频繁更新的知识，微调适合稳定的行为模式。

面试话术

“RAG 四阶段：清洗→分块→检索→生成。跟微调三个维度不同：RAG 管知识库（外部）、推理时检索、适配频繁更新；微调管参数（内部）、训练时固化、适配稳定模式。生产组合用——微调定风格，RAG 供知识。”

Q2：Chunking 策略有哪几种？

展开答案

核心原理

六种。基础四种——固定大小（按字符截断，容易切断语义）、语义切分（按段落句子边界，保持完整）、递归切分（按标题/换行/句号逐级降级切）、Token 切分（保证 Embedding 上下文窗口）。进阶两种——父子块（metadata 记录 parent_chunk_ids，检索命中子块自动拉父块）、Row-to-NL（结构化数据每行转自然语言）。论文用 Section 语义，专利 Field-split+父子块，文档递归切分，结构化数据 Row-to-NL。

面试话术

“六种策略。基础：固定大小、语义、递归、Token。进阶：父子块（专利引用链）、Row-to-NL（业务数据）。KB 类型决定策略——论文语义、专利父子块、文档递归、业务 Row-to-NL。”

Q3：混合检索 + Reranker 怎么配合？RRF？

展开答案

核心原理

混合检索 = Dense 向量（语义相似）+ Sparse 关键词（BM25 精确匹配），互补长短。Reranker 用 Cross-Encoder 对候选文档逐对深度打分重排——比 Embedding 相似度准但慢，只在初筛后的小候选集上做。RRF 是融合 Dense 和 Sparse 排名的算法——不看原始分数只看排名，用 1/(k+rank) 加权求和，解决两个检索系统分数不可比的问题。

面试话术

“混合检索 = 向量语义 + BM25 精确。Reranker = Cross-Encoder 深度重排，准但慢，只跑 Top-N 候选。RRF = 不看分数看排名，1/(k+rank) 融合，解决不同检索器分数不可比。”

Q4：HyDE / Step-Back / Multi-Query 区别？

展开答案

核心原理

HyDE——LLM 先用用户问题生成假答案，用假答案的向量去检索。假答案用词贴近专业文档，解决口语和术语鸿沟。适合论文/法律/医疗。Step-Back——回答前先退一步查背景知识，补全前置概念再回答。Multi-Query——一个问题改写成多个角度的 query，分别检索，Reranker 选最佳。适合模糊问题或简短查询。

面试话术

“HyDE 改检索向量（假答案→搜），Step-Back 改问题层级（先问’是什么’再问’怎么用’），Multi-Query 改问题角度（一个变多个）。HyDE 对术语鸿沟、Step-Back 补背景、Multi-Query 去模糊。”

Q5：路由和 Query Structuring？

展开答案

核心原理

路由三种模式——逻辑路由（该不该走 RAG）、语义路由（走哪个 KB，Embedding 匹配 KB 描述）、The Boy 的三层 KB Router（语义 80%→关键词 15%→LLM 兜底 5%，从快到慢逐级降级）。Query Structuring——用 LLM 从自然语言中提取结构化过滤参数。语义部分做向量检索，元数据部分做 SQL 过滤——两个条件叠加缩小检索范围。

面试话术

“路由三层：逻-语-LLM 兜底。80% 语义过、15% 关键词、5% LLM。Query Structuring 把自然语言拆成’搜什么’+’条件是什么’。语义走向量、元数据走 SQL，叠加缩范围。”

Q6：高级索引——RAPTOR / 多表征索引 / ColBERT？

展开答案

核心原理

RAPTOR——语义聚类→LLM 逐层总结→构建树状索引，全局问题匹配顶层树节点。多表征索引——chunk 时生成摘要存元数据，检索匹配摘要返回原文。ColBERT——保留每个 token 的向量，token 级细粒度匹配，比”一个向量 vs 一个向量”精细。父子块——metadata 记录 parent_chunk_ids，检索命中子块自动拉父块。

面试话术

“RAPTOR 树状索引、多表征=摘要索引、ColBERT=token 级匹配、父子块=血缘联动。ColBERT 最精细但索引大，RAPTOR 适合全局问题，父子块适合结构化文档。”

Q7：CRAG / Self-RAG / 自适应检索？

展开答案

核心原理

CRAG——检索后评估文档质量，置信度不够自动触发网络搜索补充。Self-RAG——生成后自我反思，没有引用或质量不够就重新检索生成。标准 RAG 一次检索一次生成，CRAG 纠错在检索阶段，Self-RAG 纠错在生成阶段。

面试话术

“CRAG 纠检索——质量不够补网络搜索。Self-RAG 纠生成——没引用或质量差就重来，直到过阈值。标准 RAG 一次过，CRAG/Self-RAG 加闭环。”

Q8：GraphRAG vs 传统 RAG？

展开答案

核心原理

传统 RAG 在向量空间做相似度搜索——搜到的 chunk 是孤立的。GraphRAG 额外构建知识图谱（实体+关系），检索时在图里遍历实体之间的路径和关系，发掘向量检索捕捉不到的间接关联。向量负责”找到”，图遍历负责”联系”。

面试话术

“传统 RAG 向量搜孤立 chunk。GraphRAG 加知识图谱——实体关系图遍历，发现向量搜不到的间接关联。向量找、图联系。适合跨文档推理。”

Q9：Lost in the Middle？怎么缓解？

展开答案

核心原理

LLM 对长上下文中间位置的信息利用率最低——Self-Attention 天然偏重首尾。缓解：Reranker 把最相关的放在开头或结尾、控制 Top-K 不过大、分段注入分批处理。

面试话术

“长上下文中间信息被忽略——Attention 偏首尾。解法：Reranker 重排把关键放两端、控制 K 不大、分段注入。本质是 Attention 架构问题，不是 Prompt 能解决的。”

Q10：RAGAS 四指标 + 诊断矩阵？

展开答案

核心原理

检索阶段——Context Precision（信号 vs 噪声）、Context Recall（有没有漏）。生成阶段——Faithfulness（有没有编造）、Answer Relevancy（切不切题）。诊断：Precision 低→加 Reranker、减小 k、提高阈值（缩范围）；Recall 低→切大 chunk、混合检索、增大 k（扩范围）；Faithfulness 低→加强 Prompt”只根据文档回答”；Relevancy 低→Query 改写+Step-Back。

面试话术

“CP 噪声→缩（Reranker 降 k）、CR 漏→扩（混合检索 大 chunk 增 k）、Faith 编→改 Prompt、AR 偏→改写 Query。Precision 和 Recall 反向操作——一个缩一个扩。”

易混淆点

  • ❌ “Recall 低加 Reranker” → ✅ Reranker 缩范围，会让 Recall 更低！Recall 低要扩范围

Q11：从零设计企业级 RAG 知识库？

展开答案

核心原理

基础四阶段——清洗、分块、检索、生成。四个加分点——一、KB 类型决定策略（论文 HyDE+Section，专利 Field-split+父子块，文档语义+Step-Back，业务 Tool Router+参数化 SQL 防注入）。二、DDD 架构（Domain 定义 ABC 接口，Infrastructure 实现，换向量库只改 Infrastructure）。三、三层 KB Router（语义→关键词→LLM 兜底，从快到慢逐级降级）。四、四阶段交付路线+评测闭环（MVP 先跑通→逐层加能力→离线 RAGAS+在线 Prometheus）。不一步到位，先做到 85 分。

面试话术

“四阶段基础+四个加分：KB 类型决定策略、DDD 依赖倒置、三层 Router 逐级降级、四阶段交付+评测闭环。核心哲学——不一步到位，先做到 85 分再优化。”
