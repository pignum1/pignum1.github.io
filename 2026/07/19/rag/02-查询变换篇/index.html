RAG 02：查询变换篇 — 把问题变好，检索才能变准

基于 RAG From Scratch Part 5-9。五种技术解决一个共同问题：用户问得不好 → 检索找不到 → 答案不对。在检索之前先改造问题。

零、本章速查表

技术 做什么 额外 LLM 调用 额外检索次数 适合场景 一句话
Multi Query 5 种不同问法各检索一次，合并去重 1 次 N 次 通用提升召回率 “多角度撒网，总能捞到鱼”
RAG-Fusion Multi Query + RRF 倒数排名融合 1 次 N 次 需要更好排序 “在多路中都靠前的，才是真正相关的”
Decomposition 复杂问题拆成子问题，逐个回答再合并 1 次 N 次 多步推理问题 “复杂问题拆开查，每个子问题都精准”
Step Back 生成更抽象的”后退问题”，补背景知识 1 次 1 次 需要先理解概念 “往上提一层，先搞懂概念再查细节”
HyDE LLM 编假答案，用假答案向量去检索 1 次 1 次 短问题、风格不匹配 “编个假答案去找真文档，假答案风格更像”

核心思想：

一、Multi Query（多角度查询）

一句话

同一个问题，用 5 种不同的问法各检索一次，合并去重。

为什么

用户问 "怎么减少 LLM 幻觉？"，实际文档可能是 "提高大模型输出可靠性的方法"。用词不同，向量匹配度低。Multi Query 自动生成多种表述，总有一种能对上。

代码

多路检索 + 合并去重

串起来

面试要点

  • 为什么比单路检索好：覆盖更多表述方式，召回率更高
  • 代价：N 路检索 = N 倍检索成本 + 1 次 LLM 调用（生成问题）
  • 去重是必须的：多路可能检索到相同的文档，不去重会浪费 Token

二、RAG-Fusion（多路召回 + 排序融合）

一句话

Multi Query + RRF（倒数排名融合），让”在多路中都靠前的文档”得到更高分。

为什么需要 RRF

Multi Query 解决了”找到更多文档”，但没有解决”哪个更相关”。如果一个文档在 3 路检索中都排第 1，另一个只在 1 路中排第 5——前者明显更值得给 LLM。

三、Decomposition（问题分解）

一句话

复杂问题拆成子问题，逐个检索+回答，再由 LLM 汇总。

两种模式

代码 — 独立回答 + 合并

面试要点

  • 什么时候用递归、什么时候用独立：子问题有依赖关系→递归；互不依赖→独立（并行，更快）
  • 和 Multi Query 的区别：Multi Query 是”同样的问题换 5 种问法”；Decomposition 是”把问题拆成完全不同的子问题”

四、Step Back（退一步问）

一句话

回答问题之前，先问一个更抽象、更基础的”后退问题”。

为什么

很多问题回答不了，是因为缺少背景知识。先退一步问概念，再回来答具体问题。

代码

面试要点

  • 和 Decomposition 的区别：Decomposition 是”往下拆”（拆成子问题），Step Back 是”往上提”（提成更抽象的问题）
  • 适用场景：具体事实性问题（”谁在什么时候做了什么”）→ 需要背景知识才能回答

五、HyDE（假设文档嵌入）

一句话

让 LLM 先编一个假答案，用假答案的向量去检索——假答案的语言风格更接近真实文档。

为什么这么神奇

用户问题和文档用词风格差异大时，直接向量匹配效果差：

为什么假答案反而更准：LLM 生成的文本语言风格更规范、更接近文档库的写作方式，向量也更”像”真实文档。

代码

面试要点

  • 为什么有效：假答案的语言风格更接近文档库，向量的”方向”更准。本质上是用 LLM 生成的规范文本替换用户的口语文本
  • 什么时候用：用户提问很短/口语化，但文档是正式/学术风格时
  • 风险：如果 LLM 编的假答案方向完全错误，检索也会跑偏
  • 替代方案：直接在 Prompt 里让 LLM 写一个搜索 query，而不是假答案

七、面试速查

Q：这五种技术什么时候用哪个？

“简单的知识问答用 Multi Query 就够了。如果需要更好的排序→RAG-Fusion。问题涉及多步推理→Decomposition。用户问得太简短→HyDE。需要先理解概念才能回答→Step Back。实际项目中最常用的是 Multi Query 和 HyDE。”

Q：每多一次 LLM 调用，延迟增加多少？为什么不担心？

“每次额外 LLM 调用约 0.5-2 秒。相比回答质量提升，这个成本是可以接受的。而且这些调用可以并行（Multi Query、Decomposition 独立模式），实际延迟等于最慢的那一次，而不是 N 次之和。”

Q：你项目中用了哪种？

“Super Agent 平台用了类似 Multi Query 的策略——对用户的金融分析问题，让 LLM 自动生成不同角度的查询词，然后用混合检索多路召回。评测结果显示检索命中率提升了约 15%。”

Q：HyDE 和 Multi Query 有什么区别？

“Multi Query 是变换问题本身（换 5 种问法），HyDE 是生成答案再去检索。HyDE 更激进（直接编答案），但风格匹配更精准。Multi Query 更保守（换问法），适用范围更广。”
