11.3：工程补全 — 流式 SSE / 分布式训练 / 推理模型 Prompt

补最后一批缺口：流式输出（用户等不了 30 秒）、分布式训练（70B 模型怎么塞进多张 GPU）、推理模型 Prompt（2026 新增考点）。

一、流式输出（SSE）

1.1 为什么 Agent 必须支持流式

生成 500 个 token 要 10 秒——用户看着白屏 10 秒直接关掉。流式输出让 LLM 生成第一个 token 就开始显示，体感延迟从 10 秒降到 0.3 秒。

1.2 SSE vs WebSocket

SSE WebSocket
方向 单向（服务器→客户端） 双向
协议 纯 HTTP 升级为 ws://
复杂度 极低，原生支持 需要 ws 库
LLM 流式 ✅ 够了 过度设计
典型场景 ChatGPT 打字效果 实时协作编辑

LLM 流式输出只需要服务器推文本给客户端 → SSE 就够了，不需要 WebSocket。

1.3 FastAPI SSE 实现

1.4 面试速答

“LLM 流式输出用 SSE（Server-Sent Events），单向推送足够了，不需要 WebSocket。FastAPI 用 StreamingResponse + text/event-stream，前端原生 EventSource API 接收。LLM 的首 token 延迟（TTFT）是关键指标——流式输出让用户感知延迟从一次生成全部改成看到第一个字的时间，从 10 秒降到 0.3 秒。”

2.4 其他优化

技术 原理 节省
混合精度 (fp16/bf16) 半精度训练，loss scaling 一半显存
梯度累积 多个 micro-batch 累积后才更新 用小 batch 模拟大 batch
梯度检查点 不存所有激活值，反向传播时重算 省激活值显存

2.5 面试速答

“训练 70B 模型用 DeepSpeed ZeRO-3 + 混合精度。ZeRO 把优化器状态、梯度、参数分片到多张 GPU——8 张 A100 就可以训。数据并行只管 batch 拆分、张量并行切权重矩阵、流水线并行切层。实际工程中三者组合：外层数据并行、中层流水线、内层张量并行——叫 3D 并行。”

三、推理模型 Prompt 技巧（2026 新增）

3.1 推理模型 vs 普通模型

推理模型（DeepSeek-R1、o1/o3）内部做了 CoT，你不需要在 Prompt 里写”Let’s think step by step”——它自己会想。

普通 LLM 推理模型
内部推理 无 有（会先内部思考再输出）
Prompt 风格 指令要详细 指令要简洁
CoT 需要在 Prompt 里要求 不需要，甚至会干扰
输出前延迟 几乎无 有（”思考”阶段）

3.2 给推理模型写 Prompt 的规则

3.3 面试速答

“推理模型（o1/R1）内部已经做了 CoT，Prompt 不需要写”一步一步思考”——反而会干扰内部推理链。原则是少说怎么做、多说想要什么。跟普通 LLM 写 Prompt 的思路是反的。”
