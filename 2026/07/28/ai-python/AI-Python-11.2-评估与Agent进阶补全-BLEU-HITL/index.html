11.2：评估与 Agent 进阶补全 — BLEU / ROUGE / PPL / Human-in-the-Loop

补两个缺口：传统评估指标（面试被问”BLEU 为什么不适用于 LLM”时要有答案）+ Human-in-the-Loop（Agent 的最后一层安全网）。

一、传统指标（BLEU / ROUGE / PPL）

1.1 为什么面试要问这个

面试官问”BLEU 有什么局限”不是考你背公式——是看你能不能区分传统 NLP 时代和 LLM 时代的评测思维。只会说”我用 GPT-4 打分”不够，要能说出”为什么不用 BLEU”。

1.2 BLEU（机器翻译评测）

公式核心：n-gram 精确匹配率 × 长度惩罚因子。

致命缺陷：LLM 的回答不是翻译——同一句话有无数种正确的表达方式。

面试话术：”BLEU 依赖精确 n-gram 匹配，无法评估语义等价的表达。LLM 对同一个问题可以有十种同样正确的回答方式，BLEU 会判其中九种为错。”

1.3 ROUGE（文本摘要评测）

公式核心：召回率——参考答案中的 n-gram 有多少出现在模型输出中。

和 BLEU 的区别：ROUGE 侧重召回（有没有漏信息），BLEU 侧重精确（有没有多信息）。

但是在 LLM 时代同样失效——同一个意思有无数种表述方式，ROUGE 只看词面匹配看不到语义。

1.4 PPL（困惑度 — 语言模型评测）

公式核心：p(真实下一个 token) 的几何平均倒数。越低越好。

局限：PPL 只衡量模型对”给定文本”的预测能力，无法评估生成质量（流畅但胡说八道的文本 PPL 也可能很低）。

1.5 为什么 LLM 时代 BLEU/ROUGE 不适用了

传统指标 核心问题 替代方案
BLEU 只能评翻译（一对一的正确译文） LLM-as-Judge
ROUGE 只看词面重叠不管语义 LLM-as-Judge / RAGAS
PPL 只测语言流畅度不测事实性 TruthfulQA / Faithfulness

1.6 面试速答

“BLEU/ROUGE 在传统 NLP 任务（翻译/摘要）中是标准，但它们依赖精确 n-gram 匹配，无法评估语义等价——LLM 对同一个问题可以有十种正确的回答，BLEU 判九种为错。LLM 时代的评测用 LLM-as-Judge（GPT-4 打分）、RAGAS（RAG 四指标）、以及 TruthfulQA/MMLU 等标准基准。”

二、Human-in-the-Loop

2.1 为什么需要

Agent 可以自主调用工具、执行代码、发邮件——但权限越大，犯错代价越大。Human-in-the-Loop 是 Agent 和真实世界之间的安全网。

2.4 设计原则

原则 说明
操作分级 P0（删数据/发邮件）→ 必须审批；P1（改配置）→ 审核日志；P2（搜索）→ 全自动
暂停不等于卡死 超时没回复 → 降级到安全默认行为
审批理由可视化 不是盲弹一个”确认/取消”，要展示 Agent 打算做什么、影响范围
审核日志 每个操作记录 timestamp + 操作内容 + 结果，方便事后追查

2.5 面试速答

“Human-in-the-Loop 是 Agent 安全体系的最后保障。三种模式：审批（危险操作前暂停等确认）、审核（正常执行+事后审查）、全自动（低风险操作）。关键设计：按操作风险分级，不是一刀切所有操作都要人点确认——那样用户体验太差。LangGraph 用 interrupt_before 实现暂停等待。”

知识点 一句话
BLEU n-gram 精确匹配 + 长度惩罚，翻译用，语义等价不行
ROUGE 文本召回率，只看词面不看语义
PPL 困惑度，越低越好，只测流畅度不测事实性
HITL 审批 危险操作前暂停，等人类确认
HITL 审核 正常执行 + 事后检查日志
操作分级 P0 审批 / P1 审核 / P2 全自动
