11.1：推理优化补全 — Tokenizer / 投机解码 / MoE

11.0 面试体系中标记的三个 P0 缺口，一篇补完。三个主题都是高频面试题：Tokenizer 是 LLM 的入口、投机解码是推理加速的前沿方案、MoE 是 GPT-4/DeepSeek-V3 的核心架构。

一、Tokenizer：LLM 的第一个环节

1.1 为什么重要

Tokenizer（分词器）决定了 LLM 看到的世界。”我喜欢吃苹果” → LLM 看到的不是汉字，是 token ID：[123, 456, 789, 234]。

面试常问：”为什么同一个句子，不同模型的 token 数不一样？”——因为每个模型有自己的 Tokenizer。

1.2 BPE（Byte Pair Encoding）— GPT 系列用的

核心思路：从字符级别开始，反复合并最高频的相邻 token 对，直到达到目标词表大小。

为什么 BPE 好用：

  • 不在词表里的词可以拆成子词："Transformer" 不在词表 → 拆成 "Transform" + "er"
  • 中文同样适用："深度强化学习" → "深度" + "强化" + "学习"
  • 不会像字符级分词那样 token 太多，也不会像词级分词那样 OOV（Out of Vocabulary）

1.3 WordPiece — BERT 用的

和 BPE 类似，但合并标准不同。BPE 选最高频的对，WordPiece 选能使训练语料似然度提升最大的对。

1.4 SentencePiece — LLaMA / GLM 用的

BPE 和 WordPiece 都假设文本已经被空格分隔了（英文自然有空格）。SentencePiece 不依赖空格——它把输入当成原始字节流，直接在字节级别做 BPE。

LLaMA 模型用 SentencePiece + BPE 就是这个原因——训练语料是多语言的，不能依赖英文的空格规则。

1.5 三个对比速查

BPE WordPiece SentencePiece
代表模型 GPT 系列 BERT LLaMA / GLM / T5
合并标准 最高频 最大似然 最高频（字节级 BPE）
空格依赖 是（英文） 是（英文） 否（字节流）
中文友好 一般 一般 好

1.6 面试速答

“Tokenizer 把文字转成 token ID 序列。主流方案三种：BPE（GPT 系列，合并高频对）、WordPiece（BERT，按似然度合并）、SentencePiece（LLaMA，字节级 BPE，不依赖空格，多语言友好）。中文模型推荐 SentencePiece 或 BPE+较大中文词表。”

二、投机解码（Speculative Decoding）

2.1 问题：自回归推理为什么慢

LLM 生成一个 token 要读完之前所有 token → 每个 decode step 串行。生成 100 个 token = 100 次串行前向传播。GPU 大部分时间在等——每次只算一个 token，GPU 利用率极低。

2.2 核心思想：用小模型”猜”，大模型”验”

2.3 为什么加速？

关键：大模型验证时是一次前向传播同时检查 4 个 draft token。

草稿模型只负责猜方向，大模型负责确认——方向对了直接过，方向错了大模型纠正。

2.4 关键约束：草稿模型怎么选

要求 原因
输出分布和大模型越接近越好 猜得准，接受率高（>80%）
比大模型小很多 猜的成本可以忽略
同一个 Tokenizer 否则 token ID 对不上

常用方案：大模型是 70B → 草稿用同一家族的小模型 7B。Llama-3.1-70B 的投机解码通常用 Llama-3.1-8B 当草稿。

2.5 面试速答

“投机解码用小模型一次猜多个 token，大模型一次验证。大模型的调用次数从 100 次降到 25 次，总延迟降低 2-3 倍。草稿模型要和大模型输出分布接近，通常选同一家族的小模型。接受率是关键指标，>80% 才有效果。”

三、MoE 混合专家模型

3.1 问题：大模型所有参数每次都用，浪费

标准 Transformer 的 FFN 层：无论输入是什么，全部参数跑一遍。模型越大越浪费——“写诗”和”算数学”用了同一组 FFN 参数。

3.2 MoE 核心思想：每个 FFN 拆成 N 个专家，每次只激活 Top-K 个

3.3 为什么有效

专家会自动分工——训练过程中 Router 学会把不同类型的 token 路由到不同的专家。比如：

  • 专家 1 擅长处理数学符号
  • 专家 3 擅长处理中文成语
  • 专家 5 擅长处理代码语法

看你的输入 token 是什么，自动激活相关的专家。

3.4 MoE 的实际模型

模型 总参数 每次激活 专家数 怎么知道的
Mixtral 8×7B 47B 13B 8 名字里的 8×7B
DeepSeek-V2/V3 671B 37B 很多 论文公开
GPT-4 据传 1.8T 据传 280B 据传 8-16 OpenAI 没说

关键数字：DeepSeek-V3 总参数 671B，每次推理只激活 37B——省了 ~18× 的计算量。

3.5 MoE 的两个工程挑战

1. 负载均衡：训练时 Router 可能”偏好”某几个专家，导致这些专家过载、其他专家闲着。

2. 推理显存：虽然只激活 2 个专家，但所有专家的参数都要装在显存里（因为不知道下一个 token Router 会选谁）。

3.6 面试速答

“MoE 把标准 FFN 拆成 N 个专家网络，每次只激活 Top-K 个。DeepSeek-V3 671B 总参数只激活 37B。核心挑战是负载均衡——训练时给路由 loss 加惩罚防止专家偏斜。推理时需要所有专家留在显存里，所以对显存总量要求高但对计算量要求低。”
