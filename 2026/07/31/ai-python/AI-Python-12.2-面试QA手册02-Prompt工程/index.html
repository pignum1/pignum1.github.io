Q1：CoT 的原理？什么时候用、不用？

展开答案

核心原理

CoT 让 LLM 先写推理过程再给答案，把隐含的思考步骤显式化。适合数学推理、多步逻辑——越复杂越需要 CoT。不适合简单事实问答、翻译、创意写作——这些场景加 CoT 浪费 token 还干扰输出。原则：问题需要多步推理才加 CoT，一步直达的不加。

面试话术

“CoT 让 LLM 写推理过程再给答案。数学/逻辑/多步推理必加；简单问答、翻译、创意写作不加——浪费 token。判断标准：需要多步思考就加。”

易混淆点

  • ❌ “ReAct 就是 CoT” → ✅ ReAct 里有 CoT（Thought 阶段），但多了一层（Action+Observation）。CoT 不调工具

Q2：Few-Shot 怎么选示例？给几个合适？

展开答案

核心原理

四个原则：覆盖边界（正面/负面/正常/异常各放一个）、和目标格式一致、从简单到复杂排列、2-5 个就够了。关键是质量不是数量——一个精心选的边界 case 比十个雷同的示例有用。

面试话术

“选例四原则——覆盖边界 case（正/负/常/异）、和目标输出格式一致、从简到繁排列、2-5 个。质量 > 数量，一个边界 case 顶十个废话。”

易混淆点

  • ❌ “示例越多越好” → ✅ 太多反而让 LLM 困惑，且浪费 Token。2-5 个精选就够了

Q3：CoT / ToT / GoT / ReAct / Reflection 的区别？

展开答案

核心原理

CoT 是一条链推到底的推理方法。ToT 每步多路探索加剪枝。GoT 分叉后的思想可以合并汇聚。ReAct 思考加行动交替，Agent 的标准工作模式。Reflection 自我评价加修正——生成后自己检查、发现问题、重新生成。复杂度从低到高：CoT → Self-Consistency → ReAct/Reflection → ToT → GoT。

面试话术

“CoT 一链到底，ToT 分叉剪枝，GoT 思想合并，ReAct 思考+行动交替（Agent 标配），Reflection 自我打分修正。复杂度：CoT < ReAct < ToT < GoT。面试就记住 ReAct 是 Agent 标准模式。”

易混淆点

  • ❌ “这些是互相替代的” → ✅ 它们是不同场景的不同工具，可以组合使用（如 ReAct 里内嵌 CoT）

Q4：结构化输出——FC vs Prompt 后处理？

展开答案

核心原理

FC 在 token 级别约束——每个 token 生成前就受 Schema 限制，不会跑偏，但依赖模型支持 FC 能力。Prompt 后处理更灵活、不挑模型，但约束发生在生成之后——LLM 可能不按格式输出，需要代码正则提取 + 校验 + 重试兜底。原则是 FC 优先、Prompt 兜底，两种不互斥。

面试话术

“FC token 级约束，硬约束但挑模型。Prompt 后处理灵活通用但需代码兜底。FC 优先、Prompt 兜底，不互斥。The Boy 用后处理因本地模型不支持 FC。”

易混淆点

  • ❌ “FC = MCP” → ✅ FC 是模型的输出格式能力，MCP 是工具连接协议，两个完全不同层面的东西

Q5：推理模型 Prompt 怎么写？

展开答案

核心原理

给推理模型（o1/R1）写 Prompt 跟普通 LLM 完全相反。普通 LLM 需要角色 + 步骤 + 格式 + 约束全部写清楚。推理模型内部已经做了完整的 CoT 推理链——你只需要告诉它要什么结果、什么格式。少说怎么做、多说要什么，Prompt 越短越好。

面试话术

“普通 LLM 写全（角色+步骤+格式+约束）。推理模型反着来——已内置 CoT，只说想要什么+什么格式，越短越好，写 CoT 反而干扰。”

易混淆点

  • ❌ “推理模型也需要写 CoT” → ✅ R1/o1 内部已推理，外部再加 CoT 会干扰内部推理链
