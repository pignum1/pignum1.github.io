RAG 05：高级检索与生成篇 — 让检索和生成形成闭环

基于 RAG From Scratch Part 15-18。前面 01-04 都在优化”怎么检索得更准”。这一章更进一步：检索完了还敢不敢信？信错了怎么办？生成的内容有没有依据？

和 04 篇的关系：04（高级索引）在 索引阶段 优化数据结构（Multi-representation / RAPTOR / ColBERT）→ 产出更高质量的候选 → 本章（05）拿到这些候选后，做精排（Re-ranking）、质量评估（CRAG）、逐句自省（Self-RAG）。04 是”源头优化”，05 是”末端校验”。实际项目中两者配合使用：先用 04 的技术建好索引，再用 05 的技术保证输出质量。

零、本章速查表

技术 做的判断 判断时机 核心机制 代价 一句话
Re-ranking Top-K 里谁更相关 检索后 Cross-Encoder 精排 多一轮模型推理（~150ms） “粗排捞候选，精排挑精华”
CRAG 检索结果能不能用 检索后、生成前 LLM 评估 → 补充/切换 Web Search 1 次 LLM 评估 + 可能 Web Search “检索完先问一句’靠谱吗’，不靠谱就上网查”

四种技术的定位：

一、Re-ranking（重排序）

一句话

向量检索是”粗排”（快但不准），Reranker 是”精排”（慢但准）。粗排捞 20 个候选，精排挑出最好的 5 个。

Bi-Encoder vs Cross-Encoder

流程

Bi-Encoder vs Cross-Encoder 对比

Bi-Encoder Cross-Encoder
怎么编码 问题和文档分别独立编码 问题和文档拼在一起编码
速度 快（文档向量可预计算） 慢（每次都要重新算）
精度 中 高（问题+文档交互）
角色 粗排（召回） 精排（重排序）
代表模型 BGE、OpenAI Embedding Cohere Rerank、bge-reranker

面试要点

  • 为什么不全用 Cross-Encoder：全库 10000 篇每篇都要和问题拼在一起跑一遍模型，太慢太贵
  • 你的项目：Super Agent 的 RAG 用了混合检索（粗排）+ Cross-Encoder Reranker（精排），面试可以直接说

二、CRAG（纠错型 RAG）

一句话

检索完了先别急着用——让 LLM 判断检索质量，不好就自动补充 Web Search 或完全切换。

问题

传统 RAG 有个致命弱点：不管检索结果是什么，LLM 都会基于它生成答案。

CRAG 在检索和生成之间加了一步质量评估。

流程

为什么需要 Web Search 作为补充

向量库再大，覆盖不了所有知识。用户问”昨天的新闻”时，向量库根本没有——这时候 Web Search 是唯一获取信息的渠道。CRAG 自动判断、自动切换，用户无感知。

面试要点

  • 核心创新：检索 → 评估 → 补救，形成闭环
  • Web Search 不是银弹：公共网络信息质量参差不齐，需要额外过滤
  • 评估的开销：多一次 LLM 调用（评估），但比”垃圾进垃圾出”的代价小得多

三、Self-RAG（自省式 RAG）

一句话

LLM 生成时自己决定：要不要检索、检索结果有没有用、生成的内容有没有依据。

和 CRAG 的区别

CRAG Self-RAG
谁做判断 一个独立的评估 LLM 生成 LLM 自己
判断时机 检索后、生成前（一次性） 生成过程中（多次）
能做什么 评估检索质量 + 补充搜索 决定要不要检索 + 判断检索结果是否相关 + 检查生成内容是否有支撑

面试要点

  • 核心创新：不是”检索完再判断”，而是生成过程中持续自省
  • Reflection Token 是训练出来的：需要在训练数据中标注这些 Token，不是靠 Prompt 就能做到的
  • 比 CRAG 更灵活：CRAG 是一刀切（好/坏/模糊），Self-RAG 是逐句判断
  • 代价：需要特殊的训练数据和模型支持，工程落地门槛高

四、Long Context vs RAG

一句话

Context 窗口能塞 200 万 Token 了，RAG 还有必要吗？有——不是因为塞不下，而是因为精准 > 全量。

Context 窗口越来越大的趋势

RAG 的三个不可替代的理由

维度 Long Context RAG
准确率 “大海捞针”问题：长文中间的细节容易被模型忽略 精准检索相关段落，不依赖模型”记住”
成本 每次把所有文档塞进 Context，Token 消耗巨大 只传相关的 Top-K 文档，Token 消耗低
推理速度 Context 越长推理越慢（注意力复杂度 O(n²)） Context 精简，推理快

六、面试速查

Q1：CRAG 和 Self-RAG 的核心区别？

“CRAG 是检索后一次性评估质量、决定是否补救；Self-RAG 是生成过程中持续自省，逐句判断检索结果有没有用、生成内容有没有依据。CRAG 是一刀切，Self-RAG 是逐句查。”

Q2：Self-RAG 的 Reflection Token 能靠 Prompt 实现吗？

“不能。Reflection Token（<RETRIEVE>、<ISREL>、<ISSUP>）需要在训练数据中标注，模型要专门训练才能理解和使用。Prompt 可以模拟类似行为，但不是真正的 Self-RAG。”

Q3：Long Context 越来越长，RAG 会过时吗？

“不会。RAG 是’精准定位’，Long Context 是’完整容纳’，两者互补。RAG 降成本、提速度、提准确率，这三个优势不因 Context 窗口变大而消失。”
