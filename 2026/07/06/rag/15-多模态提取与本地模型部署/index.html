一、多模态提取：核心原则

所有非文本内容 → LLM 生成文本描述 → Embedding → 统一成文本模态

为什么必须在入库时处理而不是检索时：检索时只有用户问题的向量，没法直接和图片像素做相似度匹配。必须提前把非文本转成文本。

2.3 两级缓存去重（核心亮点）

公司 Logo、平台 UI 截图、同一张架构图在多篇文档中反复出现。每次都调 Qwen2-VL 是巨大浪费。

2.4 级联更新

图片描述模型升级后，需要重新描述所有图片并找到引用它们的 chunk。

流程：新模型升级 → 更新 image_cache 中的 description → 查询 image_chunk_refs 找到所有引用该图的 chunk → 批量更新 chunk.content 和 embedding。

六、本地模型部署

6.1 三个模型，零 API 成本

能力 模型 大小 内存 库
Embedding BAAI/bge-m3 2.2GB ~3GB FlagEmbedding
Reranker BAAI/bge-reranker-v2-m3 1.5GB ~2.5GB FlagEmbedding

总计 ~12GB VRAM，Mac 16GB 完全够用。三个模型全部 HuggingFace 开源，数据不出本地。

6.2 模型生命周期管理

三个关键设计：

  1. Lazy Loading：模型首次调用时才加载，减少启动时间
  2. Semaphore 并发控制：防止多请求同时推理撑爆内存
  3. 动静分离：Embedding+Reranker 常驻，多模态模型按需加载/卸载

七、面试速查

Q：多模态 RAG 的核心原则是什么？

“入库时统一成文本模态。图片→Qwen2-VL 文字描述，公式→LaTeX+语义解释，表格→LLM 摘要。所有内容 Embedding 前都是文本。为什么不是检索时处理？因为检索时只有用户问题向量，没法直接和图片像素做匹配。”

Q：图片去重怎么做的？

“两级缓存。第一级 MD5 精确匹配——完全相同的图直接复用描述。第二级 dHash 感知哈希——相似度 > 95% 的图也复用。估计去重率 40-60%，大幅降低多模态 LLM 的调用量。”

Q：模型部署成本怎么控制？

“三个模型全部 HuggingFace 开源本地部署，零 API 成本。BGE-M3(2.2G) + bge-reranker(1.5G) + Qwen2-VL(4G) 共 ~12GB，Mac 16GB 就够。加上 Semaphore 并发控制和 Lazy Loading，启动快、不 OOM。”
