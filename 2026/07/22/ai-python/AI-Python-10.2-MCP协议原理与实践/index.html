10.2：MCP 协议原理与实践

MCP（Model Context Protocol）是 Anthropic 于 2024 年 11 月发布的开放协议。一句话定义：大模型的”USB-C 接口”——统一了 LLM 与外部工具、数据源的连接方式。本文覆盖协议原理、四层架构、三大原语、与 Function Calling 的本质区别，以及 The Boy Assistant 知识库的 MCP 实战。

零、本章速查表

概念 做什么 一句话
MCP 协议 统一 LLM 与外部工具的连接标准 “AI 界的 USB-C：一套协议连接所有工具”
Resources 暴露数据给 LLM 读 “文件、数据库记录、API 响应——只读”
Tools 暴露动作给 LLM 执行 “搜索、计算、发邮件——可执行”
Prompts 可复用的提示词模板 “预定义的对话模板，Server 提供”
Transport 通信层 stdio（本地进程）/ HTTP+SSE（远程服务）
JSON-RPC 协议消息格式 请求/响应/通知，MCP 的底层协议

3.1 Resources：数据（只读）

3.3 Prompts：模板（可复用）

用途：Server 端提供标准化的提示词模板，用户/LLM 可以选用。比用户手写 Prompt 更规范、更可维护。

5.1 很多人搞混

5.2 详细对比

Function Calling MCP
是什么 模型能力（LLM 能输出的格式） 协议标准（Client-Server 通信规范）
谁定义的 OpenAI / Anthropic / Google 各家不同 Anthropic 开源，社区共建
工具定义 写在 API 请求的 tools 参数里 Server 端定义，Client 通过 list_tools() 发现
工具实现 开发者自己在代码里处理 Server 端实现，Client 通过 RPC 调用
传输 HTTP API 请求/响应 stdio 或 HTTP+SSE（独立进程）
发现机制 无，硬编码 list_tools() / list_resources() 动态发现
模型兼容 只有支持 FC 的模型能用 任何 LLM 都能用（协议与模型无关）
部署 工具逻辑嵌入应用代码 Server 独立部署、独立运行

Function Calling 解决的是”LLM 知不知道该调哪个工具”，MCP 解决的是”怎么连上那个工具”。两者配合使用。

七、MCP 的优势总结

优势 说明 面试关键词
开放标准 不是某家公司私有协议，社区共建 “Anthropic 开源，MIT 协议”
模型无关 不挑模型，Claude/GPT/DeepSeek/GLM 都能用 “协议与模型能力解耦”
动态发现 list_tools() 自动发现，不用硬编码工具列表 “Server 端新增工具，Client 端零改动”
独立部署 MCP Server 独立进程，不嵌入应用代码 “工具即服务（Tool-as-a-Service）”
双传输层 stdio 本地零延迟 + HTTP SSE 远程共享 “本地工具和远程服务统一协议”
权限管控 Host 层控制是否允许调用，安全审计 “用户确认 + 白名单 + 审计日志”

八、面试速查

面试频率评估：MCP 是 2025-2026 年的差异化加分题。一线大厂 Agent/平台工程岗已经开始问，但还不是”必考题”（不像 RAG/Transformer/Attention 那样人人都会问到）。如果你主动提到 MCP + 能讲清楚和 Function Calling 的区别，效果远好于被动等面试官问。属于”拉开差距”级别，不是”不及格就挂”级别。

Q1：MCP 是什么？一句话。

“MCP 是 Anthropic 发布的模型上下文协议——统一了 LLM 连接外部工具和数据源的标准。一句话：AI 界的 USB-C，一套协议连接所有工具。”

Q2：MCP 和 Function Calling 有什么区别？（高频！）

“Function Calling 是模型的能力——让 LLM 能输出结构化的工具调用指令。MCP 是协议——定义 Client 和 Server 之间怎么通信、怎么发现工具、怎么传输数据。Function Calling 解决’LLM 知不知道调哪个工具’，MCP 解决’怎么连上那个工具’。两者配合使用：LLM 通过 Function Calling 决定调什么，通过 MCP 连接到工具去执行。”

Q3：MCP 的三大原语是什么？

“Resources（数据——文件、数据库记录等只读内容）、Tools（动作——搜索、发送、计算等可执行操作）、Prompts（模板——可复用的提示词）。记忆方式：Resource 是名词，Tool 是动词，Prompt 是模板。”

Q4：stdio 和 HTTP+SSE 两种传输方式怎么选？

“local 工具用 stdio——Client 启动 Server 子进程，零网络延迟，适合部署在同机的工具。remote 工具用 HTTP+SSE——Server 独立运行，适合需要多 Client 共享的远程服务。The Boy 的知识库用 stdio（同机），业务数据库用 HTTP+SSE（远程）。”

Q5：MCP 相比传统 API 集成有什么优势？

“三个核心优势。1）动态发现——list_tools() 自动获取工具列表，不需要硬编码。2）标准化——JSON-RPC + JSON Schema，任何语言都能实现。3）解耦——工具独立部署为 MCP Server，Agent 端不需要引入工具的实现依赖。”
