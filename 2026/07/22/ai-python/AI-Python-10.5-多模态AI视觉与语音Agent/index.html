10.5：多模态 AI — 视觉语言模型与语音 Agent

LLM 从”读文字”到”看懂图”再到”开口说话”——多模态是 2025-2026 年 AI 落地最热的赛道。本文覆盖 VLM 三种架构范式、语音 Agent 三阶段管道（ASR → LLM → TTS）、多模态 Agent 的设计模式，以及面试中最关键的几个问题。

2.2 每一段的延迟预算

语音交互的核心指标：端到端延迟 < 500ms，超过就感觉”不自然”，超过 2 秒就像”机器人”。

优化手段：

优化 效果 代价
流式 ASR（边说边识别） 等用户说完前 200ms 就开始处理 准确率略降
LLM 流式输出 不等全部生成完，首 token 就开始转语音 TTS 要支持流式输入
预测性处理 用户还在说，就开始预加载可能的结果 浪费计算
同机部署 ASR+LLM+TTS 省网络延迟 ~50ms 需要大显存 GPU

2.3 Whisper 模型选型

模型 WER RTF(实时因子) 显存 适合
tiny 12.7% 0.3× 800MB IoT / 关键词检测
base 8.2% 0.8× 1.5GB 生产环境平衡之选
small 6.4% 1.2× 2.4GB 中等需求
large-v3 5.1% 2.1× 10GB 质量优先

生产建议：base 模型 + faster-whisper（CTranslate2 加速），延迟砍半，准确率不掉。

2.4 端到端 vs 级联

级联（ASR→LLM→TTS） 端到端 S2S（GPT-4o / Moshi）
延迟 300-700ms 200-400ms（快了 ~300ms）
准确度 更高（每个模块独立优化） 略低（统一模型难兼顾）
可控性 高（每段可独立调试） 低（黑盒）
开发成本 三个模块各自选型 一个模型搞定
2025 生产选择 主流 ✅ 前沿探索

结论：2025 年生产环境还是级联为主，端到端 S2S 延迟更低但可控性差。面试时说”我们选择级联架构，ASR 用 Whisper，TTS 选型根据场景——客服用 Orpheus 追求自然度，高并发用 Kokoro 追求速度。”

三、多模态 Agent 设计模式

3.1 BeMyEyes 模式：看图的和推理的分开

为什么比 GPT-4o 好？ GPT-4o 要在一次调用里同时完成”看懂图”和”推理”——两个任务抢算力。分开后，VLM 专注看图（不需要太强），LLM 专注推理（不需要视觉能力），各司其职。

3.2 GAM-Agent 模式：游戏论驱动的多 Agent 验证

适合对准确性要求极高的场景（医疗影像、工业质检）。

四、面试速查

Q1：VLM 的三种架构范式是什么？（高频）

“浅层对齐（LLaVA）——冻住 ViT 和 LLM，只训投影层；深度预训练（DeepSeek-VL）——从头图文联合训练；Perceiver-Reasoner 分离（2025 新趋势）——轻量 VLM 看图生成文字描述，强 LLM 做推理。The Boy 知识库用的是第三种思路：Qwen2-VL 生成描述 → 文本 Embedding → DeepSeek 检索。”

Q2：语音 Agent 为什么用级联而不是端到端？

“级联架构（ASR→LLM→TTS）虽然多了一点延迟，但三个模块各自独立优化、各自独立调试、各自独立升级。端到端 S2S 延迟更低但可控性差——调不了 ASR 的准确率、改不了 TTS 的风格。2025 年生产还是级联为主。”

Q3：Whisper 怎么选模型大小？

“看场景。生产环境默认 base + faster-whisper——8.2% WER 够用，0.8× 实时因子不卡。需要高质量转录（会议纪要）用 large-v3，5.1% WER。边缘设备（IoT、离线 App）用 tiny + whisper.cpp。”

Q4：VLM 部署怎么省成本？

“三个关键——1）图片只在入库时调 VLM 生成描述，检索时不调 VLM（像 The Boy 知识库的设计）。2）能用本地小 VLM（Qwen2-VL-2B）就不用 GPT-4o。3）Perceiver-Reasoner 分离，推理用纯文本 LLM 不走 VLM。”
