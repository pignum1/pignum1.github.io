一、评估体系：RAGAS

1.1 为什么必须有评估

没有量化指标就没有优化方向——你改了个参数，不知道效果是变好了还是变差了。

1.2 四个核心指标

指标 测什么 低分怎么办
Context Precision 搜到的文档中有多少相关 → 加 Reranker
Context Recall 该搜到的搜到没 → 加混合检索
Faithfulness 回答有没有编造 → 加 Prompt 约束
Answer Relevancy 回答切题吗 → Query 改写

1.4 在线监控 vs 离线评估

离线评估（RAGAS） 在线监控（Prometheus）
测什么 策略对不对 系统活不活
频率 发版前 / 周级 实时
谁用 开发者调优 运维告警

二、监控体系：Prometheus + Grafana

2.1 六个核心指标

业务指标

指标 类型 告警阈值
search_total Counter 连续 5 分钟 = 0 → P1
search_latency (embed) Histogram P99 > 2s → P2
search_latency (rerank) Histogram P99 > 5s → P2
hit_rate Gauge < 0.3 持续 10 分钟 → P1

系统指标

指标 告警
model_loaded = 0 P0（模型未加载，所有检索失败）
model_memory_bytes > 80% 总内存 P3（即将 OOM）
pgvector 连接失败 P0（数据库挂了）

2.2 四条告警规则

级别 条件 动作
P0 模型未加载 / pgvector 断开 立即通知，自动重启
P1 连续 5 分钟零检索 / 命中率 < 0.3 通知 oncall
P2 P99 延迟 > 2s(embed) / > 5s(rerank) 告警但不唤醒
P3 内存 > 80% / 存储 > 80% 工作日处理

六、面试亮点汇总（9 条，逐条可讲）

1. “KB 类型决定策略”

不是所有数据用同一套 chunk_size+检索策略。论文用 Section+HyDE，专利用 Field+父子块，文档用 Semantic+Step-Back，业务用 Row-to-NL+Tool Router。

2. “DDD 六限界上下文”

Domain 层零外部依赖，7 个 ABC Port 接口，Infrastructure 实现。换向量库只改 Infrastructure，不改业务逻辑。

3. “专利父子块联动”

权利要求有引用链，Chunk metadata 记录 parent_chunk_ids，检索时自动拉取父块，Agent 拿到完整上下文。

4. “Tool Router + 参数化 SQL”

业务库精确数值查询用 Tool Router——LLM 提取参数 → 参数化 SQL。禁止裸 SQL 拼接，$1 占位符从协议层面防注入。

5. “图片两级缓存去重”

MD5 精确匹配 + dHash 感知哈希，相似度 > 95% 复用描述。去重率 40-60%。加上 image_chunk_refs 级联更新。

6. “三个模型全部本地免费”

BGE-M3 + bge-reranker + Qwen2-VL，HuggingFace 开源，总计 ~12GB，Mac 16GB 够用。零 API 成本，数据不出本地。

7. “Semaphore + Lazy Loading + 超时保护”

Lazy Loading：模型用到才加载，不是启动时一口气全装。没被调用的模型不占内存。

Semaphore 并发控制：Embedding 最多 4 并发，Reranker 最多 2，多模态串行。防止 10 个请求同时推理撑爆内存。

三层保护链：

不是只靠 Semaphore —— Semaphore 防 OOM，超时防无限排队，重试保证最终成功。三层配合。

8. “四阶段交付路线”

Phase 1 MVP → Phase 2 检索增强 → Phase 3 监控+MCP → Phase 4 多模态。先跑通再优化，和”先做到 85%”同一个哲学。

9. “监控评估双闭环”

离线 RAGAS 测策略，在线 Prometheus 测系统。4 级告警 + LangFuse Trace，从”不知道为什么慢”到”每段延迟可视化”。

七、面试速查

Q：你的 RAG 系统最大的设计亮点是什么？

选 9 条中和你面试岗位最相关的 3 条讲。如果是架构岗 → 讲 DDD + 四种分块；如果是算法岗 → 讲 HyDE + Tool Router + 父子块；如果是一面 → 讲策略矩阵 + 本地部署 + 四阶段路线。

Q：从 0 到 1 设计一个企业知识库，你会怎么做？

“先分析数据源——不同源用不同策略。然后四阶段交付——MVP 先跑通基础管线，再逐层加 Reranker、路由、多模态。最后上监控+评估闭环。不做过度设计，先做到 85 分。”

Q：和其他 RAG 方案比，你的有什么不同？

“大部分 RAG 系统所有数据用同一套策略。我这个是 KB 类型决定策略——论文用 HyDE 桥接口语和学术的鸿沟，专利有父子块保留引用关系，业务用 Tool Router 处理精确数值。再加上全本地模型部署和 DDD 架构，这是三个核心差异化点。”
