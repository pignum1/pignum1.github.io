存储器层次结构 (Memory Hierarchy)

在计算机系统中，我们对存储器的期望是：速度快、容量大、价格便宜。然而，这三个目标在物理上是相互矛盾的。速度越快的存储器，通常价格越贵，容量也越小。为了解决这个矛盾，现代计算机系统采用了存储器层次结构 (Memory Hierarchy) 的设计。

1. 为什么需要层次结构？

存储器层次结构的基本思想是，在 CPU 和主存之间，以及主存和辅存之间，设置不同速度、容量和价格的存储层次，并将数据在这些层次之间进行调度，以尽可能地达到高速、大容量和低成本的统一。

这种设计的有效性，主要依赖于一个重要的程序行为特性——局部性原理 (Principle of Locality)。

  • 时间局部性 (Temporal Locality): 如果一个数据项被访问了，那么在不久的将来，它很可能再次被访问。例如，循环中的变量、函数中的局部变量。
  • 空间局部性 (Spatial Locality): 如果一个数据项被访问了，那么与它地址相邻的数据项也很可能很快被访问。例如，数组的顺序访问、指令的顺序执行。

正是因为局部性原理的存在，我们可以将 CPU 当前最需要的数据存放在速度最快的存储器中，将较少需要的数据存放在较慢的存储器中，从而在整体上获得接近高速存储器的性能。

各层次的功能

  • CPU 寄存器: 直接与 CPU 的运算器和控制器交互，是 CPU 执行指令时暂存数据和地址的地方，速度与 CPU 同步。

  • 高速缓存 (Cache): 位于 CPU 和主存之间，用于存放当前 CPU 最频繁访问的数据和指令的副本。它的存在对程序员是透明的。当 CPU 需要数据时，它会先在 Cache 中查找：

    • 缓存命中 (Cache Hit): 如果找到，则直接从 Cache 中获取，速度极快。
    • 缓存未命中 (Cache Miss): 如果未找到，CPU 会从主存中读取数据，并将该数据及其相邻的数据块一起加载到 Cache 中，以备将来使用。

  • 主存储器 (Memory): 即我们常说的内存 (RAM)。用于存放正在运行的程序和数据。CPU 可以直接对其进行寻址和访问。

  • 辅助存储器 (Secondary Storage): 即硬盘 (HDD) 或固态硬盘 (SSD)。用于长期存放大量的程序和数据。它的内容在断电后不会丢失（非易失性）。主存中的数据通常来自于辅存。

3. 层次结构中的数据流动

  • Cache-主存层次: 这一层的数据交换是由硬件自动完成的，对程序员透明。其目标是解决 CPU 与主存之间的速度差异问题。

  • 主存-辅存层次: 这一层的数据交换是在操作系统的管理下完成的（例如，虚拟内存技术中的页面调入/调出）。其目标是解决主存容量不足的问题，为用户提供一个容量远大于物理主存的“虚拟存储空间”。

总结

存储器层次结构是计算机系统设计中的一个核心折衷方案。它通过巧妙地利用局部性原理，将不同特性的存储器组合在一起，使得整个存储系统在成本可控的前提下，获得了接近于顶层高速存储器的平均访问速度和底层大容量存储器的存储空间。
