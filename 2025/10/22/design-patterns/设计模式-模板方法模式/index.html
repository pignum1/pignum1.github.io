什么是模板方法模式？

模板方法模式 (Template Method Pattern) 是一种行为型设计模式，它在一个抽象类中定义了一个操作的算法骨架，并将一些步骤的实现延迟到子类中。模板方法使得子类可以在不改变算法整体结构的情况下，重新定义算法的某些特定步骤。

通俗地讲，模板方法模式就像是去银行办业务。无论你办什么业务（存款、取款、转账），基本流程（算法骨架）是固定的：取号、排队、叫号、去柜台办理。这个固定流程就是模板方法。而“去柜台办理”这一步的具体内容，则根据你办理的业务（子类）不同而不同。

模式结构

模板方法模式的结构非常简单，主要包含两个角色：

  1. AbstractClass (抽象类): 定义了一个或多个抽象方法，供子类实现。同时，它实现了一个模板方法，该方法定义了算法的骨架，并调用了那些抽象方法以及其他具体方法。
  2. ConcreteClass (具体类): 继承了抽象类，并实现了父类中定义的抽象方法，以完成算法中与子类相关的步骤。

优缺点

优点

  1. 代码复用: 将算法中通用的部分提取到父类中，提高了代码的复用性。
  2. 封装不变部分，扩展可变部分: 将固定的算法流程封装在模板方法中，而将可变的实现细节交给子类，符合开闭原则。
  3. 控制反转 (Inversion of Control): 父类调用子类的操作，而不是子类调用父类，这是一种简单的控制反转。子类只需实现特定步骤，而无需关心何时被调用。

缺点

  1. 增加了复杂性: 每个不同的实现都需要一个单独的子类，如果算法的可变部分过多，可能会导致类的数量增加。
  2. 继承的限制: 由于模板方法模式基于继承，这使得子类与父类强耦合，并且 Java 的单继承特性也限制了其使用场景。

经典应用

  1. Java 集合框架中的 AbstractList: AbstractList 是 ArrayList 和 LinkedList 的父类。它提供了 add, remove, indexOf 等方法的默认实现，这些实现都依赖于子类必须实现的 get(int index) 和 size() 等抽象方法。这就是一个典型的模板方法应用。
  2. HttpServlet: 在 Java Web 开发中，我们通常继承 HttpServlet 并重写 doGet() 或 doPost() 方法。HttpServlet 的 service() 方法就是一个模板方法，它根据请求类型（GET, POST 等）来调用 doGet(), doPost() 等方法，而具体的业务逻辑则由我们的子类来实现。
  3. Spring JdbcTemplate: Spring 框架中的各种 Template 类（如 JdbcTemplate, RestTemplate）也广泛使用了模板方法模式。例如，JdbcTemplate 封装了获取连接、创建 Statement、处理异常、关闭连接等固定流程，而将具体的 SQL 执行和结果映射等可变部分通过回调（一种更灵活的模板方法变体）交由开发者处理。
