什么是命令模式？

命令模式 (Command Pattern) 是一种行为型设计模式，它将一个请求封装为一个对象，从而使你可用不同的请求对客户进行参数化，对请求排队或记录请求日志，以及支持可撤销的操作。

通俗地讲，命令模式就像你去餐厅吃饭。你（客户端）看好菜单后，告诉服务员（调用者）你要点什么菜（比如“一份宫保鸡丁”）。服务员将你的点单写在订单（命令对象）上，然后把订单交给后厨的厨师（接收者）。

在这个过程中：

  • 你无需关心厨师是谁，也不用关心宫保鸡丁具体怎么做。
  • 服务员无需知道如何做菜，他只负责传递订单。
  • 厨师无需知道是谁点的菜，他只负责根据订单做菜。
  • 订单本身（命令）成为了一个独立的对象，它包含了所有必要信息（“做一份宫保鸡丁”）。这个订单可以被排队、记录，甚至在厨师还没开始做之前被取消（撤销）。

模式结构

命令模式主要包含以下角色：

  1. Command (命令接口): 定义了所有具体命令的统一接口，通常包含一个 execute() 方法。
  2. ConcreteCommand (具体命令): 实现了命令接口。它持有一个 Receiver (接收者) 的引用，并调用接收者的相应方法来完成请求。
  3. Receiver (接收者): 知道如何执行与请求相关的操作，是真正执行业务逻辑的实体。
  4. Invoker (调用者): 持有一个命令对象，并要求该命令执行请求。调用者不直接与接收者交互。
  5. Client (客户端): 创建具体命令对象，并设置其接收者。然后，它将命令对象与调用者关联起来。

优缺点

优点

  1. 解耦: 将请求的发送者和接收者完全解耦。发送者（Invoker）无需知道接收者是谁，也无需知道如何执行操作。
  2. 易于扩展: 可以很容易地增加新的命令，而无需修改现有代码，符合开闭原则。
  3. 支持高级操作: 命令对象可以被存储、排队、记录日志，并且很容易实现撤销（Undo）和重做（Redo）功能。
  4. 组合命令: 可以将多个命令组合成一个宏命令（Composite Command），以执行一系列复杂操作。

缺点

  1. 增加了类的数量: 对于每个简单的操作，都可能需要创建一个具体的命令类，这会导致系统中类的数量增加。

经典应用

  1. GUI 按钮和菜单项: 在图形用户界面中，一个按钮或菜单项（Invoker）被点击时，会执行一个 Command 对象。这个 Command 对象包含了要执行的操作和接收者（如一个文档对象）。
  2. 任务队列/线程池: 线程池中的工作队列可以存储 Command 对象（通常是 Runnable 或 Callable 的实例）。工作线程（Invoker）从队列中取出命令并执行，而无需知道命令的具体内容。
  3. 宏录制与执行: 用户的操作可以被录制为一系列的命令对象，然后可以一次性地回放这些命令，实现宏功能。
  4. 事务性操作: 在需要支持事务的系统中，可以将一系列操作封装成命令。如果事务需要回滚，可以依次调用每个命令的 undo() 方法。
